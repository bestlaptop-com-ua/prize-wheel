# Mid-spin-only firmware

`prize_wheel/prize_wheel.ino` is the active controller on `main`.

## Behavioral changes

- The motor never starts a second move after the wheel reaches a true stop.
- A safe predicted landing is left untouched.
- A predicted dare landing triggers same-direction mid-spin synchronization and deceleration.
- STEP pulses are generated by ESP32 LEDC, so frequency can change smoothly without repeatedly restarting a motion planner.
- STEP pulses begin while the TMC2209 outputs are disabled. The driver is then enabled at low current while the magnetic field is already rotating in the calibrated direction.
- Sustained opposite motion, stale encoder position, or excessive rotor/field speed mismatch immediately disables the outputs.
- Direction calibration is signed and versioned. Stored calibration is rejected automatically when direction-relevant firmware constants change.
- If a dare landing still occurs, the firmware reports it but deliberately does not perform a visible stop-and-spin recovery.

## Required setup

1. Flash `prize_wheel/prize_wheel.ino`.
2. Place the pointer exactly on the wedge-0 boundary and send `z`.
3. Center the pointer in safe wedge 3 or one of wedges 7-11.
4. Send `p` and keep hands clear during the approximately 9-degree direction probe.
5. Send `s` and confirm `dirCal=1`, encoder position is `FRESH`, and velocity becomes `VALID` after movement.

## First test

1. Send `v` to enable takeover logs.
2. Make moderate CCW spins.
3. Make moderate CW spins.
4. Stop immediately if the log reports `opposite-motion`, `phase-slip`, or the mechanism rattles.
5. Compare each `DECISION`, `SYNC_START`, `SYNC_LOCKED`, `TAKEOVER_END`, and `LANDED` sequence.

The controller intentionally uses low takeover current and a conservative 650 step/s² equivalent deceleration. Increase current or deceleration only after both directions engage cleanly.

## Build

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 prize_wheel
```

Target environment:

- ESP32 Arduino core 3.3.10
- TMCStepper
